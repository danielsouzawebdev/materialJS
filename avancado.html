1. Assincronismo e Promises

JavaScript roda numa única linha de execução — mas tarefas demoradas (esperar uma resposta de rede, um timer) não podem travar essa linha. Elas são delegadas ao navegador e retornam depois, via Promise.

function esperar(segundos) {
  return new Promise((resolve, reject) => {
    if (segundos < 0) {
      reject(new Error("Tempo inválido"));
      return;
    }
    setTimeout(() => resolve("Pronto!"), segundos * 1000);
  });
}

esperar(2)
  .then(resultado => console.log(resultado))
  .catch(erro => console.error(erro));
Estado da PromiseSignifica
pendingainda não terminou
fulfilledterminou com sucesso — dispara .then()
rejectedterminou com erro — dispara .catch()

2. async/await

async function exemplo() {
  console.log("Começando...");
  const resultado = await esperar(2);
  console.log(resultado);
}

exemplo();

async/await é "açúcar sintático" sobre Promises — o mesmo mecanismo por baixo, mas com cara de código síncrono, muito mais fácil de ler do que encadear vários .then(). Toda função async retorna, ela mesma, uma Promise.

Regra prática

await só funciona dentro de uma função marcada async (ou, em módulos modernos, no nível mais externo do arquivo). Esquecer o async na declaração da função é o erro de sintaxe mais comum desse tópico.

3. Fetch API

async function buscarUsuarios() {
  try {
    const resposta = await fetch("https://api.exemplo.com/usuarios");

    if (!resposta.ok) {
      throw new Error(`Erro HTTP: ${resposta.status}`);
    }

    const usuarios = await resposta.json();
    console.log(usuarios);
  } catch (erro) {
    console.error("Falha ao buscar usuários:", erro.message);
  }
}

// enviando dados (POST)
async function criarUsuario(dados) {
  const resposta = await fetch("https://api.exemplo.com/usuarios", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(dados)
  });
  return resposta.json();
}

fetch não lança erro em respostas 4xx/5xx — só em falha de rede. Por isso é preciso checar resposta.ok manualmente antes de seguir, como no exemplo.

4. Closures e escopo

function criarContador() {
  let contagem = 0;

  return function () {
    contagem++;
    return contagem;
  };
}

const contador = criarContador();
console.log(contador()); // 1
console.log(contador()); // 2

const outroContador = criarContador();
console.log(outroContador()); // 1 — independente do primeiro

A função retornada "lembra" da variável contagem mesmo depois que criarContador terminou de rodar — isso é uma closure. Cada chamada de criarContador() cria um escopo novo e independente, por isso outroContador começa do zero.

5. this, bind, call, apply

const pessoa = {
  nome: "Ana",
  falar() {
    console.log(this.nome);   // "this" é quem chamou o método: pessoa
  }
};

pessoa.falar();   // "Ana"

const falarSolto = pessoa.falar;
falarSolto();       // undefined — perdeu o contexto de "pessoa"

const falarPreso = pessoa.falar.bind(pessoa);
falarPreso();        // "Ana" — bind "trava" o this para sempre

// arrow functions NÃO têm o próprio this — herdam do escopo onde foram criadas
const pessoa2 = {
  nome: "Rui",
  falar: () => console.log(this.nome)   // this aqui NÃO é pessoa2
};

Essa é uma das maiores fontes de bug para quem está aprendendo: this depende de como a função foi chamada, não de onde foi definida — exceto em arrow functions, que fixam o this do contexto ao redor desde a criação.

6. Classes ES6

class Animal {
  constructor(nome) {
    this.nome = nome;
  }

  falar() {
    return `${this.nome} faz um som`;
  }
}

class Cachorro extends Animal {
  falar() {
    return `${this.nome} late: Au au!`;
  }
}

const rex = new Cachorro("Rex");
console.log(rex.falar());   // "Rex late: Au au!"
Reconheceu isso?

class, constructor, herança com extends, sobrescrita de método — são exatamente os mesmos conceitos de POO vistos em C#, só com sintaxe de JavaScript. Encapsulamento, herança, polimorfismo: os mesmos quatro pilares, outra linguagem.

class ContaBancaria {
  #saldo = 0;   // campo privado — o # torna inacessível de fora da classe

  depositar(valor) {
    this.#saldo += valor;
  }

  get saldo() {
    return this.#saldo;
  }
}

const conta = new ContaBancaria();
conta.depositar(100);
console.log(conta.saldo);    // 100
console.log(conta.#saldo);    // SyntaxError — campo privado

7. Módulos ES6

// arquivo: animal.js
export class Animal {
  constructor(nome) { this.nome = nome; }
}

export const TIPOS = ["cachorro", "gato", "pássaro"];

export default function criarAnimalPadrao() {
  return new Animal("Sem nome");
}
// arquivo: main.js
import criarAnimalPadrao, { Animal, TIPOS } from "./animal.js";

const a = new Animal("Rex");
console.log(TIPOS);
<!-- no HTML, módulos precisam do type="module" -->
<script type="module" src="main.js"></script>

export default é usado para o "valor principal" do arquivo (só pode haver um por arquivo); export nomeado permite vários por arquivo, importados entre chaves. Módulos dividem o código em arquivos menores e reutilizáveis, em vez de um único script gigante.

8. Tratamento de erros

function dividir(a, b) {
  if (b === 0) {
    throw new Error("Não é possível dividir por zero");
  }
  return a / b;
}

try {
  console.log(dividir(10, 0));
} catch (erro) {
  console.error("Algo deu errado:", erro.message);
} finally {
  console.log("Isso roda sempre, com ou sem erro");
}

// erro customizado
class ErroDeValidacao extends Error {
  constructor(mensagem) {
    super(mensagem);
    this.name = "ErroDeValidacao";
  }
}

try {
  throw new ErroDeValidacao("E-mail inválido");
} catch (erro) {
  if (erro instanceof ErroDeValidacao) {
    console.log("Erro de validação:", erro.message);
  }
}

Criar classes de erro customizadas (estendendo Error) permite diferenciar, no catch, que tipo de problema aconteceu — útil quando o mesmo bloco precisa reagir diferente a um erro de rede versus um erro de validação, por exemplo.

Projeto do nível: buscador de usuários do GitHub

  • Um campo de texto onde o usuário digita um nome de usuário do GitHub
  • Ao enviar, uma função async busca https://api.github.com/users/NOME com fetch
  • Mostra na tela o avatar, nome e bio retornados, usando manipulação do DOM
  • Trata o caso de usuário não encontrado (status 404) mostrando uma mensagem amigável, sem quebrar a página
  • Usa uma class Usuario para organizar os dados antes de exibir, com um método exibir()
